# R0 baseline — текущий DOP853 bake (TASK_RKN12)

Этап R0, ветка `rkn12-bake` от `Q-RK-TASK`
(`0d87ada8f8e63f2feb0aa00757eb0f0a48646ae0`). Код игры не менялся: измерялся
production-путь `EphemerisBaker.BakeToFiles` с текущим fixed-step DOP853.

## Reference (§5)

* **2-body** (`Outdoors`, `ContactZone`): аналитическая кеплерова рельса того же
  тела. Для двухтельной задачи относительное движение — точный Кеплер с
  μ = μ_родителя + μ_поддерева; это независимый эталон, не DOP853.
* **4-body** (`Example4`): dd-Taylor, order 32, tolerance 1e-30, max step 86400 с,
  старт из **точного** начального состояния `RunBake` (копия
  барицентрической коррекции). В R0 — конечный узел на 1.2/10/100 лет.
  Плотное независимое сэмплирование и 1024 года — R3/R5 (решение владельца
  2026-11-15: Taylor не гонять по умолчанию; 1024 года — consistency/energy).
* **Tighter DOP853** (60 с, phase 0.002) — только consistency, не независимый
  reference.

Ошибка 2-body и 4-body — **доставленная**: она включает квантование BG3
(`QuantBudgetMeters=2`), то есть именно то, что видит рантайм.

## Ограничения R0

* Плотной независимой ошибки на всех узлах 4-тельного пресета нет: dd-Taylor
  возвращает только конечное состояние, а перезапуск на каждый узел стоит
  O(N) полных интегрирований. Endpoint + tighter-DOP853 consistency — база R0;
  плотное сравнение — R3/R5 (BACKLOG B-RK2).
* Импульс/COM по доставленным файлам не измеримы: `BakedEphemeris` хранит
  только смещения от родителя, состояния корня нет; восстановление корня из
  P=0 делает P/COM тождественно нулевыми. Нужен лог внутри `RunBake` (R2).
* 1.2-летние прогоны длятся 20–60 мс; CV до 11–27%. Для временных гейтов R4
  использовать 10 лет и медиану 5 с CV ≤10%.
* 1024-летний dd-Taylor для 4-тельного пресета **не запускался** (решение
  владельца; оценка ~1 ч). 1024 года помечены как consistency/energy, не как
  endpoint-reference (§8.5).
