# Study/framework: сравнение интеграторов «работа – точность»

Цель: показать числами, в каких ситуациях какой интегратор точнее и дешевле, для орбит планет и для аппарата, и чтобы добавление нового интегратора было одной правкой.

## Что внутри

| Файл | Роль |
|---|---|
| `StudyOde.cs` | `StudyProblem` (задача без привязки к движку), `StudyConfig`, `StudyContext` (единственный способ вызвать силу, считает вызовы и бюджет), `StudyStops` (чекпойнты + разрывы силы) |
| `StudyIntegratorApi.cs` | `IStudyIntegrator`, базовые классы `FixedStepIntegrator` / `AdaptiveIntegrator` (драйверы шага, посадка на чекпойнты, кап шага) |
| `StudySteppers.cs` | RK4, явный РК с FSAL (DOPRI5, DOP853), PEFRL, Y6/Y6C, Kepler-split (WH), leapfrog |
| `Dop853Coefficients.cs` | Таблицы DOPRI5 и DOP853 (A, B, C, E3, E5), сгенерированы из SciPy |
| `KeplerUniversal.cs` | Универсальный пропагатор Кеплера в приращениях (эллипс/парабола/гипербола) |

| `StudyBridge.cs` | **Единственный файл, знающий движок**: строит `StudyProblem` из кейсов Test549 и планетных фикстур, тесты 552/553 |

## Как добавить интегратор

1. Шагер: `IFixedStepper` (один шаг) или `IAdaptiveStepper` (пробный шаг, возвращает нормированную ошибку, принят при `<= 1`). Силу вызывать **только** через `ctx.Rhs(t, y, dy)`. Работу вне RHS (решение Кеплера, итерации неявных стадий) объявлять `ctx.CountAux(n)`: она оценивается калибровкой по времени, а не на глаз.
2. Класс-наследник `FixedStepIntegrator` или `AdaptiveIntegrator`: `Name`, `Family`, `ExpectedOrder` (для фиксированных), `Supports(...)`, `CreateStepper(...)`. Диапазон сетки менять только если стандартный не подходит (`ControlRange`).
3. Одна строка в `StudyRegistry.All()`.

`Supports` обязан вернуть `false` там, где метод неприменим (сила зависит от скорости или массы, нет центрального тела): строка тогда выводится как `n/a` с причиной, а не ранжируется по неверному ответу.

## Как читать таблицу

Стоимость = вызовы RHS-эквивалента, нужные, чтобы достичь цели по ошибке (лог-лог интерполяция между двумя прогонами, окружающими цель; экстраполяции нет).

| Метка | Смысл |
|---|---|
| число | цель окружена прогонами, стоимость интерполирована |
| `<=N EDGE` | даже самая грубая проверенная точка уже лучше цели: N — верхняя граница, не результат |
| `not reached` | самая мелкая точка или бюджет RHS остались выше цели (цензурирование, не «дорого») |
| `skip` | цель ниже порога шума эталона (`FloorMargin` × floor) |
| `n/a` | метод неприменим к задаче |

Победитель выбирается только среди ячеек с числом; если какая-то `EDGE`-ячейка может быть дешевле, ответ помечается `unresolved`.

Блок `Findings` под таблицей перечисляет всё, что делает число недостоверным: эталон не сертифицирован, ошибка растёт при уменьшении шага (округление), наблюдаемый порядок не совпадает с ожидаемым, шаг упёрся в кап, прогоны упёрлись в бюджет.

## Что исправлено по сравнению с матрицей Test549

| Проблема | Решение здесь |
|---|---|
| Победитель = край сетки (42 из 51) | сетка подбирается автоматически: грубый конец ослабляется, пока ошибка не выйдет выше самой слабой цели; есть бракет и интерполяция |
| Кап шага 600 с делает стоимость адаптивных методов независимой от допуска | адаптивные методы бегут дважды: без капа и с производственным капом; кап-связанные прогоны помечаются |
| WH с ошибкой, растущей при уменьшении шага | Kepler-дрейф в приращениях (`KeplerUniversal`); диагностика «ошибка растёт при уменьшении h» |
| Стоимость только в вызовах RHS | `CountAux` + калибровка веса решения Кеплера; ms показываются отдельно, в Debug помечаются |
| Разный учёт вызовов (DOPRI5 7/6 на шаг, `fsal=false` после отказа, перезапуск на чекпойнтах) | один драйвер для всех, FSAL сохраняется при отказе и на чекпойнтах; формулы вызовов зафиксированы самотестом |
| DOP853 только с оценкой E5 и показателем 1/8 | оценка Хайрера `err5² / sqrt(err5² + 0.01 err3²)` |
| Симплектические методы на силе, зависящей от скорости/массы | `Supports` → `n/a` |
| Недостигнутые цели не видны | статус `not reached` + строка «Findings» про бюджет |
| Абсолютные метры для всех сценариев | относительные цели от `ScaleLength` (и абсолютные, если заданы) |

## Переменные окружения

| Переменная | Пример | Действие |
|---|---|---|
| `P1B_INTEGRATORS` | `RK4,DOP853-adaptive,WH-Y6` | подмножество методов (опечатка → ошибка со списком известных) |

| `P1B_PLANET_YEARS` | `10` | горизонт планетного теста |

## Ограничения (честно)

- Код **не компилировался и не запускался** при подготовке (в среде не было `dotnet`). Математика ядра проверена на Python-зеркале: пропагатор Кеплера, таблицы, оценка ошибки DOP853, порядки RK4/DOPRI5/PEFRL/Y6/leapfrog. Первый прогон `Test551` — проверка того, что C# делает то же.
- Эталоны остаются теми, что строит Test549 (лунный пролёт не сертифицирован; на 1000 витках чувствительность к формулировке силы 8.5 м). Фреймворк это помечает, но не исправляет.
- Боевые интеграторы (`StepForward`, `StepForwardDop853`) здесь не обёрнуты: фреймворк сравнивает методы на общем RHS. Сравнение с боевым путём остаётся в Test549.
- Для WH возмущение считается как разность полной силы и кеплеровой (потеря точности порядка `eps*|a|` на пинок); при необходимости отдавать возмущение из задачи напрямую.
