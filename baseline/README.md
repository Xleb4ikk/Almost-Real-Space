# baseline: эталонная машина и политика сравнения

## Эталонная машина

Побайтные хэши и логи в этом каталоге сняты на:

- Windows (win32), 32 логических ядра;
- .NET SDK 10.0.401, runtime Microsoft.NETCore.App 8.0.24;
- ветка `feature/contact-physics`.

## Политика (по приёмке фазы 0)

1. **Побайтный гейт (SHA-256) действителен только на эталонной машине.**
   Сравнение хэшей трейсов (`baseline/traces/*.csv` против
   `baseline/parity-legacy/*.csv`) и хэшей из `summary.txt` — только здесь.
2. **На других машинах и в CI побайтное сравнение не применять.** Сравнение
   числовое, с допуском:
   - детерминизм (Test280, фаза 10) — относительная погрешность 1e-9
     (сравнение на одной и той же машине, разные разбиения кадров);
   - трейсы — по числам сценариев (время касания, v_n, v_t, режим, обломки)
     в допусках соответствующих кейсов, а не по хэшам файлов.
3. Причина расхождения — платформенная арифметика (libm/CPU), а не код:
   `Test29_DescentChain` даёт дрейф 6.52e-5 м на Linux и 1.96e-4 м на Windows
   при пороге 0.01 м в обоих случаях. Test29 не использует файлы WIP, вошедшие
   в ветку, поэтому версия кода ни при чём.
4. Хэши фиксируются в отчёте фазы (`baseline/phase0_report.md`) и в
   `baseline/parity.txt`; при смене эталонной машины или рантайма baseline
   переснимается целиком с записью в отчёт.

## Состав каталога

- `xunit.txt`, `fast.txt`, `slow.txt` — логи наборов (per-case время: `[Name] ok in N ms`).
- `traces/` — эталонные трейсы S1–S6 (текущий VesselStep), `summary.txt` с хэшами.
- `parity-legacy/` — копии S1–S5, снятые слепком кода ДО выноса 0.4 (S6 появился позже).
- `parity.txt` — таблица паритета до/после 0.4.
- `phase0_report.md` — отчёт фазы 0.
