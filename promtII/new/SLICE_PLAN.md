# Вертикальный срез: колайдеры ракеты в игре

Цель: ракета из деталей садится в игре на плоскую площадку, склон, крышу здания и ВПП на
вращающейся планете; опоры пружинят; сильный удар рвёт стык. Орбитальные перелёты не меняются.

## 1. Что уже сделано и проверено (в патче)

Чистый C#, без Unity, покрыт тестами стенда:

| Файл | Что делает | Тесты |
|---|---|---|
| `Simulation/ContactZone/SiteFrame.cs` | Точный переход (восток, север, вверх) ↔ мир, с учётом вращения планеты | Test304, Test305 |
| `Simulation/ContactZone/ContactZoneGate.cs` | Решение о входе в зону: только посадка, гистерезис | Test300–303 |

Результаты здесь: Test300 (орбита 200 км: 0 кадров в зоне, min |v_rel| 7788 м/с), Test301 (вход
300 м/с: 0 кадров), Test302 (посадка 100 м, 5 м/с: зона включается), Test303 (гистерезис 100/350/450 м,
скорость 130 м/с), Test304 (ошибка обратного перехода 0 м, 3.6e-12 м/с), Test305 (покой на высоте 2 м
через 2 ч: 0 м/с относительно места).

## 2. Почему орбитальная точность не меняется

1. Патч не меняет ни одного файла орбитального расчёта: `SimulationRunner`, `VesselStep`,
   `SpacecraftPhysics`, интеграторы, события SOI и атмосферы — без правок.
2. Гейт зоны получает позицию и скорость **по значению** и возвращает только решение. Он не пишет
   в состояние корабля (тест Test300 показывает, что на орбите решение всегда «вне зоны»).
3. Зона включается только при высоте над рельефом < 300 м **и** скорости относительно поверхности
   < 60 м/с. На орбите (7.8 км/с) и на входе в атмосферу (сотни м/с) зона не включается по построению.
4. Пока зона не активна, код Unity ничего не делает (`ContactZoneHost` возвращается из `LateUpdate`).
5. Единственная правка игрового кода (см. раздел 4) — пропуск одного шага, которого не бывает, пока
   зона неактивна.

Проверка для тебя: тот же орбитальный сценарий в игре до и после патча даёт одинаковые позиции
(сравнение побитово, сценарий: корабль на орбите 200 км, 2 часа варпа). Здесь это подтверждено
стендом: полный быстрый набор (см. раздел 5).

## 3. Что нужно проверить в редакторе Unity (черновики в `unity_draft/`)

Черновики **не входят в патч**: их не компилировали. Пока они не проверены, в проект не копируем.

- `ContactZoneHost.cs` — владеет зоной: вход/выход, запись состояния корабля, эффективная гравитация
  кадра места (гравитация − ускорение планеты по орбите − центробежная от вращения).
- `ContactZoneProxy.cs` — строит тела по `PartDefinition`: Rigidbody с массой детали, коллайдеры
  (Box/Sphere/выпуклая призма для цилиндра), `FixedJoint` с `breakForce = JointStrengthNewtons`.
  Тензор инерции — автоматический от коллайдеров (отклонение от точного тензора из фазы 1 — см. 6).
- `TerrainPatch.cs` — MeshCollider 129×129 вершин на ±150 м из функции `ITerrainModel`, с высотой
  и нормалью из той же функции.

Порядок проверки в редакторе:
1. Скомпилировать черновики в тестовую сцену. Ошибки API Unity 6 — править на месте.
2. Сцена: одна ракета (T1 из JSON), плоская площадка. Запустить: зона включается, ракета садится,
   стоит 10 с без дрожания (порог — по наблюдению, записать число).
3. Склон 15°, удар 5 м/с: стык рвётся по `breakForce`, отломок падает.
4. Здание: посадка на крышу (SiteBox), удар о стену.

## 4. Точка подключения (единственная правка игры)

В `SimulationRunner.Update`, сразу после проверки `Paused`/`Ship == null`:

```csharp
if (ContactZoneHost.Active) return; // зона контакта ведёт корабль сама
```

Пока зона не активна, `ContactZoneHost.Active == false` и строка ничего не меняет. Для Unity-части
нужен `ContactZoneHost` в сцене с ссылками на `SimulationRunner`, `ContactZoneProxy`, `TerrainPatch`.

Открыто: время симуляции в зоне должно продвигаться (планета движется по орбите). Сейчас
`SimulationRunner` стоит, пока зона активна. Нужен маленький метод `VesselStep.AdvanceTime(dt)`
без орбитальной логики — это правка `VesselStep`, её сделаю после проверки черновиков.

## 5. Регрессия

Полный быстрый набор стенда — см. результат в ответе. Стенд не компилирует Unity-код, поэтому
он проверяет орбитальную математику и посадку в стенде, но не игру. Игру проверяешь сценарием
из раздела 2.

## 6. Известные ограничения среза

- Кориолис не учитывается (порядок ω·v ≈ 1e-3 м/с² при посадке; для вертикального среза допустимо).
- Тензор инерции деталей в Unity автоматический, не точный из фазы 1. Для столкновений это приемлемо,
  для точного вращения при тяге — нет (фаза 8).
- Здания и ВПП: только рельеф в срезе. Коллайдеры SiteBox подключаются на шаге 4 раздела 3.
- Вращение корабля при посадке не моделируется: корабль стоит вертикально (фаза 8).
- PhysX не детерминирован между машинами. Для посадки в игре допустимо; для орбит не используется.
- Время симуляции в зоне — см. раздел 4 (открыто).
